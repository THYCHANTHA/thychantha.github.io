Khmer Speech Data Quality

Validation checks and a leakage-aware quality benchmark for Khmer speech-recognition data, run on Google's open Khmer corpus (OpenSLR SLR42).

Open full page View on GitHub

Problem

Open, well-documented Khmer recordings are scarce, so every dataset must be checked before training a recogniser. Can a model tell clean recordings from degraded ones, and is the evaluation honest?

Overview

An independent continuation of a 2024 ITC course project on Khmer ASR data collection (no material from that project is reused), plus a consent-first design for a community recording platform.

Methodology

  • Per-clip checks of audio integrity, levels, silence, signal-to-noise and Khmer transcripts
  • Quality benchmark comparing task framing (speech vs non-speech, clean vs noisy speech)
  • Random split versus split by speaker, always against a simple non-ML baseline

Technologies

  • Python
  • Audio Processing
  • Scikit-learn
  • ASR
  • Data Quality

Results

  • Corpus: 2,906 recordings, 16 male speakers, 3.97 hours, all 48 kHz 16-bit mono, every transcript 100% Khmer script
  • The checks found 335 clips (11.5%) with more than 1.5 s of leading or trailing silence and 214 recordings sharing a sentence with another, which matters when splitting data
  • Clean vs noisy speech grouped by speaker: best model (SVM) reaches 0.985 accuracy, falling to about 93 to 94% for noise at 20 dB SNR and for babble and brown noise

Speech against non-speech noise scored 1.000 for all five models, so a high score in that framing says nothing about recording quality.
